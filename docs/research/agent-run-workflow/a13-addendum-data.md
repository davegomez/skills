- Weighted units: `weight()` of `report.py` (input 1, cache write 5 min 1.25, 1 h 2, cache read 0.1, output 5, 1 price for all models). Percentiles: the same `q()` as `report2.py` (index `int(p*(n-1))`, no interpolation). Context of a call = input + cache read + cache write.
- Agent instance = 1 (session, agent ID). "Calls" = API calls of the instance. Worker = `worker-high`, `worker-medium`, `worker-low`. "all-sub" = every subagent (workers, `general-purpose`, `Explore`).
- Tools per API call: tool_use blocks / API calls, over all subagents. This reproduces the 1.19 of `report.md` F3 on the report window (section 1b), so `report.md` used all subagents, not only the workers.
- Exploration share: the report gives the families (`grep -n`, `sed -n`, `cat`, `wc -l`, plus `Read`) and 46%, but not an exact rule. E1 = `Read`, `Grep`, `Glob`, and `Bash` whose first command (after `cd ... &&`) is `grep`, `rg`, `cat`, `wc`, or `sed -n`. E2 = E1 plus `head`, `tail`, `ls`, `find`, `nl`, `awk`, `stat`, `tree`, `jq`, `command ls`, and read-only `git` (`diff`, `show`, `log`, `status`, `ls-files`, `grep`, `blame`, `rev-parse`, `cat-file`, `branch`, `worktree`). Denominator: all tool calls of the subagents. On the report window E2 gives 46.1% and E1 41.1% (section 1b), so E2 is the rule that reproduces the 46% of the report; E1 is the narrow reading. Both are shown.
- Repeated in-agent reads: the definition of `report2.py` section 4: for each (session, agent, file), reads after the first; main sessions count as agents. "Per week" = raw count x 7 / (days from the first to the last call of the run). This reproduces the 382 of the report on the report window.
- Task classes: the `description` of the subagent (keyword match, as `report.md` 1). Priority: `correction` (case-insensitive substring), then `review`, then `fold`, then other. Share = units of the instances in the class / all units of the run (main included). The variant "stem" counts `\bcorrect` (it adds A10 descriptions that start with "Correct").
- Pi: the same files as `report.md` (`~/.pi/agent/sessions/*/*.jsonl`, `usage.cost.total` of each assistant message, unique `responseId`). A Pi session belongs to a run when its start time falls between the start of this run's orchestrator session and the start of the next run's (A10 2026-11-14T21:34Z, A11 2026-11-15T16:36Z, A12 2026-11-16T03:53Z, A13 2026-11-16T16:30Z to the cut) and its working directory has `costo`. - A correction round is not a field in any file. The count is my reading (reviews with a BLOCKING finding); orchestrator corrections done without a worker (the orchestrator edits a file itself) are not seen in subagent descriptions.
- The exact exploration rule of `report.md` (46%): the families are named but not the full rule. My E2 gives 46.1% on the report window (section 1b), so I use it as the matching rule; that it is the same rule as the report is an inference from 1 number.
- Work outside the Claude logs: the Pi reviews and the Rex panes are not Claude API calls. Pi is counted from its own logs (section 2); the `rex` pane polls appear only as the main-session tool calls that ran them.
- A13 gates outside the final summary (batch gates, per-batch run time) are not part of the unit count except as the tool calls that ran them.
- A10 per-week figure of repeated reads for a run shorter than a week is a scaled value, not an observation of a week.
