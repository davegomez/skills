# Domain docs

## Layout and reading rules

This repo uses a single-context layout.

Before exploring:

- Read root `CONTEXT.md`.
- Read relevant architectural decision records in `docs/adr/`.

If either is absent, proceed silently. Create domain documentation
through the domain-modeling skill when terms or decisions are resolved,
rather than scaffolding empty documents.

## Vocabulary

Use the terms defined in `CONTEXT.md` when naming domain concepts.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## Decisions

Explicitly flag proposals that contradict an existing ADR.
Name the ADR and explain why the decision should be reconsidered.
