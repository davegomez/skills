### Rewritten prompt

```text
Make our marketing website load faster, focusing on the home page, which reportedly takes about 10 seconds to load on mobile.

Assumption: the desired outcome is that mobile visitors can see the main message and use the primary call to action sooner—not merely achieve a better performance score.

First check access to the website URL, source repository, local build instructions, and browser performance tools. Check whether existing mobile performance measurements are available. Identify missing dependencies; do not assume access, install paid services, or treat the reported 10 seconds as a measured baseline.

Establish a reproducible baseline:
- Identify what the reported “load” delay corresponds to: first useful content, largest contentful paint (LCP), interactivity, or the load event.
- Use Chrome DevTools Performance and Network traces, or available equivalents, to inspect cold-cache mobile loads. Fix and record the device profile, network/CPU throttling, browser, and build mode.
- Measure repeated runs, retaining individual measurements and their median. Capture LCP and when the primary call to action becomes usable.

Work from raw request waterfalls and main-thread traces, not just an aggregate Lighthouse score. Identify the actual critical path: for example, server response, discovery of the main image, render-blocking resources, font loading, or JavaScript execution. Use only causes supported by the measurements.

Aim for median mobile LCP of 2.5 seconds or less using critical-path reduction under the same test conditions as the baseline. If one approach stalls, try the next evidence-supported approach within the available time and budget. Keep “demonstrably faster” as the required outcome; report the stretch target separately as met or missed.

Make focused, reversible changes. Preserve the page’s message, visual identity, accessibility, primary call to action, and existing consent and analytics behavior. Do not hide essential content, remove functionality, or optimize solely for an audit score.

Borrow experimental-design methods: compare baseline and candidate builds under matched conditions, repeat measurements, and distinguish stable improvements from run-to-run noise. Borrow adversarial testing: check whether the faster page merely postpones essential work, introduces layout shifts, or leaves the call to action unusable.

Report changed files, measured before/after results, test conditions, remaining bottlenecks, and any unverified claims.

With my approval only: deploy to production, change hosting or paid services, introduce new third-party data sharing, or add recurring performance monitoring or CI enforcement.

Judge: repeat the matched mobile browser measurements and run available functional checks, supplemented by a visual and keyboard smoke test. Pass when the home page’s relevant load milestone is reproducibly faster beyond observed measurement variability, its primary call to action is usable no later, and the preservation checks pass. Report LCP stretch attainment separately; missing measurements leave performance improvement unverified.
```

### Ledger

- `altitude`: Moves from a faster load event to earlier visibility and use of the homepage’s message and call to action; stays within homepage scope.
- `depth`: Adds dependency checks, raw browser traces, a reproducible baseline, and evidence-ranked fixes; requires website/source access and available browser tools.
- `depth`: Adds a 2.5-second median mobile LCP stretch target and alternative approaches when a fix stalls; preserves “demonstrably faster” as the required outcome.
- `range`: Uses experimental design to separate improvements from measurement noise, and adversarial testing to detect deferred work or broken usability; adds local verification effort.
- `altitude`: Gates production deployment, infrastructure spending, new data sharing, and recurring monitoring behind approval; grants no additional authority.
- Skipped lenses: none.
- Unresolved owner actions: provide or confirm the website URL, repository, and available access; clarify any time or budget limits; approve gated actions only if desired.
