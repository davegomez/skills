# Android 17 safe error-feedback pass

## Session boundary

- [Observed] Direct inspection ran on 2026-09-06 against AVD `pixel_a17` on `emulator-5554` using ADB and the emulator UI only.
- [Observed] The device reported Android release 17/API 37, fingerprint `google/sdk_gphone16k_arm64/emu64a16k:17/CP31.260623.012/16064790:user/dev-keys`, and a 1280×2856 display at density 480.
- [Observed] The Contacts notification permission was declined; no permission was granted.
- [Observed] No account, web source, purchase, send, call, saved contact, saved alarm, created folder, persistent deletion, or other persistent save was used.
- [Observed] Temporary form text was removed by Discard, Back, Cancel, or Clear text before leaving its workflow.

## Catalog decisions

- [Observed] Settings' query-specific no-results state was added to [`../../../docs/android/lists-content-feedback.md`](../../../docs/android/lists-content-feedback.md) because it combines query echo, explicit no-results copy, and a Tips & Support suggestion not represented by the existing generic empty-state entry.
- [Observed] Messages' existing recipient-first entry in [`../../../docs/android/forms-and-controls.md`](../../../docs/android/forms-and-controls.md) was updated with the directly observed no-error and “Send to 123” candidate states rather than creating a generic recipient-validation pattern.
- [Observed] Clock's existing modal time-picker entry was updated with the directly observed text-input mode and unchanged-value result rather than creating a separate generic validation pattern.
- [Observed] Contacts and Files did not gain canonical error patterns because no application-authored validation error was reachable without pressing a save or creation action.
- [Inferred] The silent retention or rejection observed before a commit action should not be generalized as adequate error feedback.
