# Observed patterns by shared UX problem

This comparison includes only UX problems with direct support in both platform catalogs. The linked entries remain platform-specific observations from one iOS 27.0 Simulator and one Android 17 Emulator. Rows align **problems**, not equivalent components: differences in placement, geometry, semantics, and interaction are preserved below.

| UX problem | iOS observation | Android observation | Evidence-safe distinction |
| --- | --- | --- | --- |
| Move among peer destinations and show the current destination | [Floating bottom navigation dock](../ios/navigation-and-presentation.md#floating-bottom-navigation-dock): a detached translucent dock whose selected item uses blue text/icon and a tinted capsule in Files and Photos | [Bottom navigation with selected destination](../android/navigation-and-presentation.md#bottom-navigation-with-selected-destination): an edge-aligned labeled row with a filled selected indicator in Clock, Phone, Maps, and Contacts; saved dumps report `selected="true"` | Both expose peer destinations, but the observed container geometry and item arrangements differ. iOS evidence here establishes visible selection; Android evidence additionally establishes saved hierarchy state. |
| Find content or settings | [Search field with dictation affordance](../ios/forms-and-controls.md#search-field-with-dictation-affordance) is a rounded resting field in Settings, Files, Messages, and Shortcuts | [Search-led top surface](../android/navigation-and-presentation.md#search-led-top-surface) can be a field or transforming icon; [search focus mode](../android/interactions-and-accessibility.md#search-focus-mode-with-explicit-exit) shows focused Settings and Messages states | [Observed] The iOS error-feedback pass retained a focused Settings search state; Android retained focused Settings and Messages states. [Unconfirmed] Dictation was visible but not activated on iOS. |
| Explain an unmatched search and provide query recovery | [Observed] [Centered empty state](../ios/lists-content-feedback.md#centered-empty-state) includes a Settings variation that repeats `zzzz-no-match`, says to check spelling or try a new search, and clears back to the list | [Observed] [Query-specific no-results recovery](../android/lists-content-feedback.md#query-specific-no-results-recovery) repeats `zzzzzzzz`, suggests Tips & Support, and retains Back and Clear text actions in Settings | [Observed] Both Settings apps directly showed query-specific zero-match feedback and a clearing path. The iOS catalog treats it as a variation of a cross-application empty-state pattern; the Android catalog keeps its distinct recovery treatment application-specific. [Unconfirmed] Neither state establishes a search failure or platform-wide error component. |
| Explain an empty collection | [Centered empty state](../ios/lists-content-feedback.md#centered-empty-state) uses a muted symbol/title cluster in Files and Shortcuts | [Illustrated empty state](../android/lists-content-feedback.md#illustrated-empty-state) uses explanatory copy, illustrations, and sometimes a primary action in Messages, Contacts, and Files | Both distinguish empty from populated content; visual emphasis and next-action treatment differ. |
| Focus a structured creation or editing task | [Full-screen task surface](../ios/navigation-and-presentation.md#full-screen-task-surface) and [grouped form rows](../ios/forms-and-controls.md#grouped-form-rows) were observed in Calendar and Contacts | [Structured create-contact form](../android/forms-and-controls.md#structured-create-contact-form) and [recipient-first composition form](../android/forms-and-controls.md#recipient-first-composition-form) were observed in Contacts and Messages | These are different application flows. No cross-platform save, validation, or completed-submission behavior was tested. |
| Expose secondary actions without replacing the base context | [Anchored overflow menu](../ios/interactions-and-accessibility.md#anchored-overflow-menu-application-specific) was observed only in Files | [Contextual overlay menu](../android/navigation-and-presentation.md#contextual-overlay-menu) was observed as an anchored Chrome panel and a Messages account sheet | The iOS evidence is application-specific; Android includes two geometrically different overlays. They are not classified as one component. |
| Request or explain protected-capability access | [System permission alert](../ios/forms-and-controls.md#system-permission-alert) was captured for location and notifications | [Permission prompt boundary](../android/interactions-and-accessibility.md#permission-prompt-boundary) includes a Contacts system dialog and application-authored Maps/YouTube Music explanations | A system alert and an in-app primer are separate presentation types. No permission was granted in either evidence run. |
| Give visible controls programmatic names | [Accessibility-labeled visible controls](../ios/interactions-and-accessibility.md#accessibility-labeled-visible-controls) were activated by XCTest labels | [Semantic labels for icon-only actions](../android/interactions-and-accessibility.md#semantic-labels-for-icon-only-actions) were retained as `content-desc` values in UI Automator dumps | These automation observations do not establish VoiceOver or TalkBack order, announcements, or usability. |

## Evidence boundaries

- Cross-platform scope is limited to the linked catalog entries and their retained screenshots.
- Application-specific evidence stays application-specific even when another platform addresses a similar UX problem.
- Sign-in walls are not treated as permission prompts, unchecked switches are not treated as unavailable controls, and a still screenshot is not used to infer animation timing.
- Application-level zero-match feedback is kept separate from system permission prompts and Contacts' unsaved-change confirmation; none is used as evidence for the others.
- Concepts observed on only one platform remain in that platform's catalog and are intentionally absent here.
- See [coverage](../../research/coverage.md), [limitations](../../research/limitations.md), and [uncertain findings](../../research/uncertain-findings.md) for inspected and untested states.
